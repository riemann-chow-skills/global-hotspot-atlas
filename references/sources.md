# 数据源与抓取策略

## 一、内置新闻源

`scripts/fetch.mjs` 默认并发抓取下列 RSS/Atom 源，任一失败不影响整体：

| 源 | 语言 | 覆盖 |
|---|---|---|
| 中新网 | 中文 | 综合，更新快 |
| 中新网·国际 | 中文 | 国际时政 |
| 人民网·国际 | 中文 | 国际时政 |
| 新浪·国际 | 中文 | 国际时政 |
| BBC World | 英文 | 全球 |
| The Guardian | 英文 | 全球 |
| Al Jazeera | 英文 | 中东偏重 |
| DW World | 英文 | 欧洲/非洲 |
| WSJ World | 英文 | 全球，财经偏重 |
| Nikkei Asia | 英文 | 亚洲，产业偏重 |

脚本对每个源做 9 秒超时、按 charset 解码（兼容 GBK）、失败单独标注。正常网络下通常 6–9 个源可用。

## 二、换源 / 加源

写一个 JSON 文件，用 `--feeds` 传入：

```json
[
  { "name": "某站", "url": "https://example.com/rss.xml", "w": 1.0 }
]
```

- `w` 是源权重（0.8–1.2 之间），影响热度打分，权威通讯社可以给 1.1。
- 只支持 RSS 2.0 / Atom / RDF 三种格式。判断方法：打开 URL 能看到 `<item>` 或 `<entry>` 标签即可。
- 中文源若出现乱码，说明 charset 声明不规范；脚本会先按响应头、再按 XML 声明解码，仍失败则按 UTF-8 处理。这种情况建议换源。

## 三、抓不到东西时怎么办

按这个顺序降级，不要卡在脚本上：

### 1. 放宽时间窗

```bash
node scripts/fetch.mjs --hours 168 --limit 50 --out raw.json
```

小源更新慢，48 小时内可能只有几条。

### 2. 换用 WebSearch（最可靠的兜底）

脚本依赖外网直连，某些环境会被拦。WebSearch 走的是检索通道，通常可用。建议这样组织检索：

```
冲突：<当前月份> 冲突 停火 军事 最新
政治：<当前月份> 大选 峰会 制裁 外交 最新
经济：<当前月份> 央行 利率 关税 油价 最新
科技：<当前月份> 芯片 人工智能 监管 最新
气候：<当前月份> 地震 洪水 台风 气候大会
社会：<当前月份> 抗议 罢工 移民 疫情
```

每个面向取 1–2 条最有代表性的事件，凑够 10–14 条即可。检索结果里通常带地名，可以直接填 `location`。

### 3. 用 GDELT（可选，需注意限流）

GDELT 的 DOC API 无需 Key，但**限制每 5 秒一次请求**，超了直接返回 429：

```
https://api.gdeltproject.org/api/v2/doc/doc?query=ceasefire&mode=artlist&format=json&maxrecords=50&timespan=24h
```

返回的 `articles[]` 含 `title` / `url` / `domain` / `seendate` / `sourcecountry`，但**没有经纬度**，仍需自己配坐标。只在其他源都不通时使用，且每次请求之间至少等 6 秒。

## 四、地名匹配是怎么做的

`assets/gazetteer.json` 内置约 130 个高频地名（首都、主要城市、冲突热点、关键海峡），每个含中文名、英文别名、经纬度。

匹配逻辑：

1. 中文别名做子串匹配，英文别名做小写子串匹配
2. 长名优先（"新加坡"不会被更短的词抢先）
3. 命中 6 字以上的长名直接采用

**局限**：只能识别内置地名。遇到地名库里没有的地点（小城市、新热点），脚本会留空，需要手工补坐标。补的时候查一下大致经纬度填进 `location` 即可，精确到城市中心就够。

## 五、热度分怎么算的

```
heat = 30
     + 时效分（越新越高，最多 +26）
     + 强度词命中（突发/重大/死亡/breaking/killed… 每次 +7，上限 +18）
     + 类别权重（冲突 +8 / 政治 +5 / 其他 +2）
     + 有坐标（+6）
     + 源权重（× 6）
```

最终夹在 8–99 之间。去重时同一事件被多源报道会再 +1。

这套分数只用来**排序和视觉分层**，不代表真实重要性。人工改写时如果觉得某条被低估，直接调 `heat` 即可。

## 六、去重规则

标题去掉标点后取二元组集合，Jaccard 相似度 > 0.72 判为同一事件，保留热度高的那条，把另一个来源追加到 `also_from`。

这意味着：

- 同一事件的中英文报道**不会**被合并（二元组完全不同），会保留两条。这时应人工合并，否则地图上会出现两个挨着的点讲同一件事。
- 标题措辞差异大的同一事件也可能漏合并。人工编辑时留意一下同城事件。
